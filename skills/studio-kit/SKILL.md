# studio-kit

studio-kit is the studio's own toolkit for client websites: a vetted library index, a hardened Astro starter, a client-repo template, and the forks the studio keeps under `github.com/KDVassen`. This skill tells you how to choose and use what is in it, and what to do when a job needs something that is not.

Everything here serves one product: fixed-price client websites, handed over to clients who then own them. That is why licences and maintenance matter as much as looks.

## The non-negotiables

Read [references/rules.md](references/rules.md) once per project. The short version:

1. **Nothing fabricated.** No invented reviews, testimonials, client names, logos, statistics or ratings, not even as layout placeholders. Use designed empty states. Concept work is labelled "Concept — not a real client".
2. **WCAG 2.2 AA is the floor.** Contrast is computed, never assumed. Visible focus, 44×44 px targets, keyboard paths, one `h1`, landmarks, `lang="en-ZA"`.
3. **Reduced motion is respected everywhere,** and a CSS media query cannot stop a JavaScript library (see below).
4. **Budget per page:** TBT ≤ 150 ms, CLS ≤ 0.02, LCP ≤ 2.0 s, JS ≤ 30 KB gzip, first load ≤ 450 KB. Lighthouse mobile ≥ 95 in every category.
5. **Every dependency's licence must let the client keep it.** No GPL/AGPL, no Commons Clause, no paid tiers, nothing `study-only`. Notices are kept and shipped.
6. **Nothing outside the index without approval** (see "Adding a library").

## Decision order: use the cheapest thing that works

Work down this list and stop at the first rung that does the job:

1. **Plain HTML and CSS.** Native `<details>`, `<dialog>`, `popover`, CSS scroll-snap, `:has()`.
2. **Native browser animation.** CSS scroll-driven animations (`animation-timeline: view()`/`scroll()`), cross-document view transitions, CSS `@property` backgrounds. 0 KB. Gate with `@supports` and the reduced-motion query. Patterns in [references/patterns.md](references/patterns.md).
3. **Your own small snippets** from patterns.md: the 227-byte reveal snippet, split-text spans.
4. **One JavaScript animation library per project.** Motion by default (works without React and in React islands). anime.js for timeline-heavy plain-JS work. GSAP only for a premium brief, and only with the licence carve-out below. **Never two of Motion, anime.js and GSAP in one project.** At most one smooth-scroller (usually none).
5. **A React island,** only when a component genuinely needs React.

## Stack: Astro + React islands

Client sites are Astro (decision D12). Pages are `.astro` and ship no JavaScript unless something asks for it.

- Interactive widgets: native elements first (`<details>`, `<dialog>`, `popover`) styled with daisyUI. For a complex widget (modal, tabs, toast), Accessible Astro Components; note its package entry adds about 9 KB gzip of CSS for all its components, so use it once a page genuinely needs one. Then Basecoat's vanilla JS. Reach for Base UI, React Aria or shadcn only on an island.
- Islands: `client:visible` for below-the-fold, `client:idle` for non-urgent above-the-fold, `client:load` only when the island must work at first paint. Avoid `client:only` unless the component cannot render on the server. One island per job; never hydrate a whole page.
- Icons render at build time (`@lucide/astro` or `astro-icon`): 0 KB client JS.
- **A React island costs about 68 KB gzip of React runtime on its own,** more than twice the 30 KB page budget. Until the operator settles how to treat this, any page with a React island needs the operator's explicit, recorded budget exception. Prefer Astro components, native elements or Basecoat.
- **Content Security Policy is on** (`astro.config.ts`): Astro hashes its own inline scripts and styles. Never use inline `style=""` attributes or `'unsafe-inline'`; style with classes. Add any external script host (analytics, embeds) to `security.csp.scriptDirective.resources`.
- Measure. After adding an island, run the build and check the page's JS against the 30 KB budget before moving on.

## Using the index

1. Open [references/library-index.md](references/library-index.md) and start at **Quick lookup: I need X**.
2. Check the entry's **use**: `ship` may go into client code; `study-only` must never enter a client repo (Aceternity, React Bits, Origin UI/coss, Locomotive Scroll).
3. Install with the **pinned version** from the entry. Before pinning a newer version, confirm its release date (npm registry) is within 12 months and its LICENSE file is unchanged. If the licence changed, stop and tell the operator.
4. Apply the entry's **reduced motion / a11y** note, and its **Watch** note if it has one. Recurring ones: Lenis ≥ 1.3.26 only; Paper Shaders ≥ 0.0.77; shadcn's class-variance-authority fails the 12-month rule (vendor it); Chart.js leaves the 12-month window on 2026-10-13 unless it releases; never install Bklit's `stat-card` items (paid, non-transferable icons); never use code under Bklit's `LICENSE-STUDIO.md`.

## Forks

The studio forks are for study and for carrying studio-specific changes. **Client builds install from npm, pinned.** Use a fork only when it carries a change the studio made:

- Make the change on a branch in the fork, tag it (e.g. `studio-1.0.0`), and set `"modified": true` for it in `forks.json`.
- Install the tagged fork by git URL pinned to the tag or commit SHA, never a branch.
- A modified fork stops receiving automatic monthly syncs; whoever modified it owns merging upstream security fixes.
- Apache-2.0 forks (Babylon.js, ECharts, react-spectrum): keep NOTICE and mark changed files.
- GSAP was not forked: its licence grants no right to modify or redistribute.

## Reduced motion: who stops what

| Mechanism | Stopped by the CSS `prefers-reduced-motion` query? | What you must do |
|---|---|---|
| CSS transitions, keyframes, scroll-driven animations | Yes | Put motion inside `@media (prefers-reduced-motion: no-preference)` |
| View transitions | No (browsers don't switch them off) | Add the reduced-motion rule from patterns.md |
| Motion, anime.js, GSAP, three.js, Lottie, Paper Shaders | **No** — they write inline styles or draw to canvas | Check `matchMedia` first and **dynamically import the library only when motion is allowed**, so reduced-motion visitors download none of it |
| Lenis | Only from v1.3.26 | Pin ≥ 1.3.26 |
| AutoAnimate, Number Flow, Astro `<ClientRouter />`, Accessible Astro Components | Yes, built in | Leave the defaults on |

Never start the LCP element at `opacity: 0`. Never animate prices, legal text, concept labels or real statistics into place.

## Licences and notices

- Run `python scripts/notices.py` from the client project root before every staging deploy and at handover. It writes `THIRD_PARTY_NOTICES.md` (name, version, licence, licence text) and `docs/handover/dependencies.md`, and **fails** on GPL/AGPL, Commons Clause, unknown licences, or any `study-only` package.
- **GSAP carve-out:** if GSAP is used, the handover documents must state that GSAP is licensed to the client directly by Webflow under its "Standard No Charge" licence and is excluded from the studio's modify/sublicense/transfer grant. Keep every `@license` header.
- Copy-paste code (shadcn, Magic UI, Bklit registry items) carries no headers. Add its notice to `THIRD_PARTY_NOTICES.md` by hand; `notices.py` lists these under "Copied source" when they are recorded in the project's `PROJECT.md`.
- Record every third-party asset (fonts, icons, images) in the licence list with name, version, licence and holder (client-build rule 10).

## Adding a library that is not in the index

1. Check `library/research-2026-10-01.md`. If the candidate was already researched or excluded, use that verdict.
2. Otherwise delegate to the **library-scout** helper with the need and the candidate. It verifies licence (from the LICENSE file), latest release date, maintenance, size and reduced-motion handling, and proposes an index entry.
3. **Ask the operator to approve** before installing anything. Approved entries are added to `library/data.py` and the index is regenerated with `python library/build_kit.py`.

## Before you hand anything over

- `npm run build` passes with zero warnings you have not explained.
- `python scripts/notices.py` passes.
- The QA and compliance helpers have run, and every CONFIRMED finding is fixed or explicitly accepted by the operator.
